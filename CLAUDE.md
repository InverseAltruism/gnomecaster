# Gnomecaster

In-game AI helper for World of Warcraft. The player types into an addon panel; a desktop companion app answers with text and actions: waypoints, the quest arrow, raid marks, macros, action bar placement, key bindings, an allowlist of console variables, and explanations of recent Lua errors.

The code is the Wowpilot prototype imported on 2026-10-16 (see `docs/PROGRESS.md`). The repo is named gnomecaster, but every identifier in the code still says Wowpilot. Whether and how to rename is an open decision.

## Layout

- `addon/Wowpilot/`: the addon (Lua 5.1, WoW API). Load order is the TOC: Core, Json, Errors, Context, Beacon, Inbox, Actions, UI, Request.
- `addon/Wowpilot_Inbox01` to `60`: load-on-demand reply slots, generated by `tools/make_inboxes.py`. Do not edit them by hand.
- `companion/wowpilot_companion.py`: the desktop app, one file, Python 3.9+ and Pillow.
- `tests/`: simulation harness. Real addon code runs on a mocked WoW API (`wowmock.lua`), the real companion code plays its part (`driver.py`), and `render.py` turns the drawn beacon into a fake screenshot.

## How the two halves talk

Addons cannot use the network or write files during play, so both directions go through the file system.

- Addon to companion (`Beacon.lua`): the request JSON is packed as `"WP"`, protocol byte, 2-byte length, adler32, payload. It is drawn as a grid 96 cells wide, 3 px per cell, 3 bits per cell, in the top-left corner for two frames, then `Screenshot()` is called. The companion watches `Screenshots/`, decodes new files, and deletes only those that contain a beacon. The payload limit is 2400 bytes; `Request.lua` drops context detail over 5 levels until it fits.
- Companion to addon (`Inbox.lua`): the companion writes `WowpilotInbox({...})` into `inbox.lua` of every slot from the requested one up to 60. The addon calls `LoadAddOn` on the next unused slot. Each slot loads once per UI session; `/reload` resets them. Replies carry `sid` (per UI load) and `rid` (per request) and are ignored when either does not match.
- Ready signal (experimental): each slot has an empty `ready.ttf`. The companion writes a real font into the next slots when a reply is ready, and the addon probes it with `EditBox:SetFont`. A signal counts only after the addon has seen it go from not ready to ready; otherwise the addon falls back to timed polling.

## Trust boundary

Model output is untrusted. The companion's `sanitize()` keeps only known action types and scalar fields, and `lua_value()` escapes everything it writes into Lua. The addon re-validates every action in `Actions.lua` (`check`) before running it. Navigation and marks run at once; macro, bar, bind and setting changes wait for Apply unless `/wp auto on`. Settings are limited to `CVAR_ALLOW`.

## Constants mirrored across Lua and Python

These must change together. No test checks that they agree yet.

| Constant | Lua side | Python side |
|---|---|---|
| reply slot count (60) | `addon/Wowpilot/Core.lua:6` | `companion/wowpilot_companion.py:46`, `tools/make_inboxes.py:6` |
| protocol version | `Core.lua:5` | `wowpilot_companion.py:47` |
| grid width (96) | `Beacon.lua:17` | `wowpilot_companion.py:45` |
| marker colours | `Beacon.lua:24` | `wowpilot_companion.py:48` |
| packet header layout | `Beacon.lua:51` (`Pack`) | `wowpilot_companion.py:49`, `_decode_at` |
| action types | `Actions.lua` `handlers` | `ACTION_TYPES`, `SYSTEM_PROMPT` |
| TOC Interface list | `addon/Wowpilot/Wowpilot.toc:1` | `tools/make_inboxes.py:7` |

After changing the slot count or the Interface list, run `python3 tools/make_inboxes.py` and commit the regenerated slots.

## Tests

Needs a Lua 5.1 interpreter (WoW runs Lua 5.1), python3 and Pillow. This server has no Lua package. Build 5.1.5 in a scratch directory from https://www.lua.org/ftp/lua-5.1.5.tar.gz (sha256 `2640fc56a795f29d28ef15e13c34a47e223960b0240e8cb0a82d9b0738695333`, `make posix`).

    LUA=/path/to/lua TMPDIR=/path/to/scratch bash tests/run_all.sh | tee run.out
    grep -c '^PASS' run.out; grep -c '^FAIL' run.out

`run_all.sh` exits 0 even when scenarios fail (each scenario is piped into grep without pipefail), so count the FAIL lines until that is fixed.

## Game constraints the code relies on

- Lua 5.1 only: no `goto`, no `//`, no integer subtype.
- Nothing runs in combat. Macro, bar and binding APIs are protected there, and Midnight (12.x) returns secret values that addon code may not compare or do arithmetic on. Every value sent out goes through `ns.Plain` or `ns.IsSecret`.
- Each `Context.Collect` section runs under pcall, so an API missing on one game flavor cannot break a request.
- Not yet proven on a real client: that `Screenshot()` from an addon yields a readable grid, that load-on-demand files are re-read from disk mid-session, and that the `SetFont` ready signal works. The 10-minute test in `README.md` covers these.
